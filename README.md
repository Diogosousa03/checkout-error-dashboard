# Checkout Error Dashboard — design (Week 7)

An internal **Streamlit** dashboard (Python) that reads checkout-error data from
Sentry and renders it fed by the error catalogue. Standalone project, following the
team's conventions (uv + hatchling, Pydantic v2, pydantic-settings, structlog, PyYAML).

## Goal

Turn the standardized Sentry data (codes, `flow_phase`, `payment_method`,
severity…) into a small internal portal with the core views:

- Errors by funnel stage (`flow_phase`) — the drop-off view
- Top errors (joined with the catalogue: description + severity)
- Errors by payment method
- Errors by severity (fatal vs error)
- Error volume over time

## Architecture

```
  Catalogue (config/catalogue.yaml)
              │
   Streamlit app (Python)  ──►  Sentry API
   (queries + join + views)     (events / discover)
```

Because **Streamlit runs server-side (Python)**, it queries the Sentry API
directly — the secret token stays in the process (via pydantic-settings). No
separate frontend, no proxy, no CORS. The app fetches counts, joins them with the
catalogue, and renders the views — all in one Python app.

## The 4 pieces (one doc each)

1. [Catalogue as config](./1-catalogue-config.md) — `config/catalogue.yaml`, loaded
   and validated with Pydantic (`catalogue.py`).
2. [Sentry API](./2-sentry-api.md) — the data source; the httpx client that queries
   error counts by tag (`sentry.py`); the auth token.
3. [Server-side data access](./3-backend-proxy.md) — no separate proxy: Streamlit is
   server-side, so it calls Sentry directly and keeps the token safe.
4. [Views (Streamlit)](./4-frontend.md) — the dashboard views rendered in `app.py`.

## Project structure

```
dashboard/
├─ pyproject.toml               # uv + hatchling, deps
├─ uv.lock                      # (generated by uv)
├─ config/
│  └─ catalogue.yaml            # the catalogue as config        ← piece 1
└─ src/error_dashboard/
   ├─ settings.py               # pydantic-settings (token, org, project)
   ├─ sentry.py                 # Sentry API client (httpx)      ← piece 2
   ├─ catalogue.py              # load/validate the catalogue    ← piece 1
   └─ app.py                    # the Streamlit app (views)      ← piece 4
```

## Tech stack (team conventions)

- **Python 3.11+**, managed with **uv** (pyproject.toml + uv.lock), build backend **hatchling**.
- **Streamlit** + **pandas** — the portal / views.
- **httpx** — HTTP client for the Sentry API.
- **Pydantic v2** + **pydantic-settings** — models and config via env.
- **structlog** — structured logs to stdout.
- **PyYAML** — declarative config in `config/*.yaml`.

## MVP

Build **one view end-to-end first** (errors by `flow_phase`): settings → sentry
client → one query → render a bar chart in Streamlit. Once that works, the other
views are the same pattern with a different group-by.

## Dependencies (needed before building)

- A **Sentry API token** with read access to the org (from the mentor / Sentry admin).
- The org slug and project id for the wallet errors.
